# 重点关注 UP：固定推荐格

## 使用

1. 打开 UP 主页，右上角菜单选择「重点关注」，点击「加入重点关注」。可以添加多位 UP。
2. 刷新首页推荐，第 4、24、44……个视频位置优先显示这些 UP 的视频，带特殊底色和「✓ 喜欢的 UP」标记。
3. 其余位置按普通推荐的原始顺序展示，不再提供 25% / 50% / 75% 占比设置。原来添加的 UP 和通知开关保留。
4. 首页「重点关注」卡片显示新投稿，点击「管理」可调整或移除 UP。新视频系统提醒、声音和横幅设置保持可用。

本功能只改变本机首页推荐，不修改 B 站的关注关系或服务端推荐参数。

## 固定格规则

- 每 20 个视频仅第 4 格允许额外插入喜欢的 UP；没有可用候选时显示普通推荐，不显示专属标记。
- 翻页按当前列表的实际视频总数继续计算。多个 UP 的可用候选轮流插入，跨页先排除已经显示的视频。
- 普通推荐自然出现喜欢的 UP 时仍保留，不人为移除或标成固定推荐格。
- 有固定推荐格时首页横幅不抽走列表视频，保证列表中的第 4、24、44 格计数准确；刷新从第一格重新开始。
- 候选同样经过屏蔽 UP、不感兴趣、内置和 JSON 过滤插件。

## 看过不再推荐

- 播放进度达到视频长度的 90% 即视为接近看完，将 BV 号持久保存在本机 DataStore。
- 此后刷新或获取下一页时，首页普通推荐和喜欢的 UP 候选都排除这些 BV 号。
- 重启应用仍保留，清除应用数据或卸载会删除记录；不会删除历史、收藏或 UP 主页中的视频。
- 多分 P 视频只在最后一 P 达到阈值时排除整条 BV，避免只看完第一 P 就误判。
- 不回溯本次安装前的历史播放记录；手动拖到 90% 也按当前播放进度记入。

## 新投稿提醒

- 从空间投稿接口读取每位 UP 最近 20 条，缓存 5 分钟，最多同时请求 3 位 UP。
- WorkManager 约每 15 分钟检查，系统省电和网络限制可能延后。
- 只提醒加入后发布且未见过的新投稿；首次添加不批量提醒历史投稿。
- 通知按 UP 合并，使用独立高重要性渠道；没有通知权限时首页仍显示未读。
- 进入视频或达到看完阈值会清除首页未读状态。
- 取消重点关注会删除该 UP 的候选缓存、未读和检查状态。接口失败保留缓存并在后续周期重试。

## 验证

PriorityCreatorPolicyTest 覆盖固定格、任意分页边界、普通推荐顺序、去重、候选不足、多 UP 轮换、90% 边界和重复提醒条件。
没有新增项目依赖。构建与测试结果见交付目录 BiliPai-verification.txt；设备上的播放和通知效果尚未验收。
